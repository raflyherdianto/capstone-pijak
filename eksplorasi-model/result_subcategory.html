Inference Latency & Runtime
XGBoost Latensi Sangat Rendah (< 1 ms)

Matematika berbasis decision tree XGBoost terkompilasi sangat ringan. Sangat efisien jika diekspos melalui REST API mikroservis.

ARIMA Latensi Menengah (~20 - 50 ms)

Memerlukan pemanggilan pustaka statsmodels Python yang membebani CPU karena operasi matriks statistika tradisional.

Prophet Latensi Tinggi (> 100 ms)

Inference Prophet membutuhkan penyusunan komponen additif (tren, musiman) yang melibatkan kalkulasi kompleks di tingkat backend Python.

LSTM Latensi Menengah (~10 - 30 ms)

Menggunakan model neural network PyTorch. Memerlukan overhead forward-pass tensor, tetapi masih cukup cepat untuk inferensi waktu-nyata pada CPU.

KNN Latensi Rendah (~2 - 5 ms)

Mencari tetangga terdekat dari set data pelatihan. Kecepatan inferensi sangat bergantung pada ukuran dataset historis yang disimpan di memori.

Data Pipeline & Retraining
XGBoost Pipeline Rekayasa Fitur Rumit

Bergantung pada fitur lags, rolling windows, dan selisih waktu (*differencing*). Memerlukan Feature Store (seperti Feast) atau database untuk agregasi data on-the-fly.

ARIMA / Prophet Retraining Otomatis Berkala

Sangat terikat dengan data historis terdekat. Harus di-retrain setiap ada titik data baru masuk (harian/mingguan) agar tidak kehilangan akurasi.

LSTM Retraining Overhead Sangat Tinggi

Membutuhkan fase pelatihan deep learning (epochs, optimization step) menggunakan PyTorch. Sangat berat untuk retraining harian jika terdapat ribuan subkategori komoditas.

Skalabilitas & Stabilitas Sistem
XGBoost / RF Robust dan Skalabel

Sangat stabil melayani ribuan jenis komoditas paralel secara bersamaan tanpa resiko crash jika ada data pencilan (outlier) ekstrem.

ARIMA Rawan Gagal Konvergensi

Algoritma optimasi numerik ARIMA (seperti L-BFGS-B) sering gagal konvergen atau crash saat dilatih otomatis pada data real-world yang tidak stasioner atau ber-outlier.

Prophet Dukungan Hari Libur Nasional Otomatis

Sangat baik dalam mendeteksi dan beradaptasi terhadap libur Lebaran dan Ramadhan secara bawaan, meminimalisir intervensi manual pada kode pipeline.

KNN Stabilitas Komputasi Tinggi

Sangat stabil karena operasinya hanya menghitung jarak Euclidean/Manhattan. Bebas dari masalah konvergensi, tetapi memakan memori seiring bertambahnya ukuran data.

Rekomendasi Utama Deployment Skala Produksi

Berdasarkan perbandingan performa akurasi statistik dan kelayakan teknis operasional, rekomendasi deployment dibagi menjadi dua skenario utama:

1. Skenario Akurasi & Prediksi Jangka Pendek (Pilihan Utama): SARIMA Murni merupakan pemenang mutlak secara akurasi statistik dengan rata-rata R² Score mencapai 0.8166 dan MAPE terkecil sebesar 0.37%. Model ini sangat direkomendasikan jika sistem menggunakan pipeline otomatis yang matang (seperti Apache Airflow) untuk melakukan retraining secara berkala (misal harian) di background worker dan memiliki handling error untuk mengatasi error konvergensi numerik. Namun, untuk beberapa komoditas musiman/volatile seperti Daging Ayam Ras Segar dan Beras Kualitas Super, model SARIMAX (dengan Exog Kalender) memberikan hasil yang lebih baik dengan memanfaatkan fitur kalender is_weekend.

2. Skenario Operasional Skala Besar (1.000+ Komoditas & Wilayah): XGBoost adalah pilihan paling tangguh. Meskipun XGBoost memiliki error rata-rata yang lebih tinggi pada pengujian baseline ini (R² Score: -0.0854, MAPE: 1.51%), XGBoost memiliki latensi inferensi sub-milidetik (< 1 ms), stabil secara matematis (tidak pernah crash saat inferensi/training), serta sangat hemat biaya komputasi untuk melayani ribuan model secara paralel.

3. Alternatif Model Non-Linear (Deep Learning): LSTM menunjukkan performa terbaik di antara model berbasis Machine Learning/Deep Learning non-linear, dengan rata-rata R² Score 0.4750. Ini jauh mengungguli Random Forest (0.1570) and XGBoost (-0.0854), menjadikannya kandidat kuat jika pola tren jangka panjang sangat kompleks dan non-linear.
